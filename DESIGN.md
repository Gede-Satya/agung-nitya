# Agung Nitya — Design System & Experience Direction

This document is the single source of truth for the Agung Nitya website.

Reference this file whenever generating, editing, reviewing, or implementing UI, 3D scenes, animation, layout, typography, or content.

The website is an immersive digital presentation of Agung Nitya's SIMRS platform.

Its visual language combines:

* Oryzo-inspired spatial product storytelling
* Apple's restraint and precision
* Linear's interface discipline
* premium enterprise technology aesthetics
* healthcare credibility

The result must feel premium, calm, cinematic, precise, sophisticated, and trustworthy.

It must NOT feel cyberpunk, gaming-oriented, sci-fi, Web3, crypto-inspired, or like a generic AI-generated futuristic website.

---

# 1. Creative Direction

## 1.1 Core Concept

The website should NOT behave like a conventional SaaS landing page.

Instead, present the Agung Nitya SIMRS platform as a sophisticated technological artifact existing inside a dark spatial environment.

The experience should feel closer to:

* an interactive technology film
* a premium product showcase
* a digital exhibition
* a cinematic technology presentation

than:

* a SaaS dashboard
* a corporate template
* a hospital website template
* a conventional marketing landing page

The website communicates technology primarily through:

* spatial composition
* typography
* 3D visualization
* camera movement
* controlled motion
* editorial storytelling

rather than excessive UI.

---

## 1.2 Design Keywords

* Premium
* Minimal
* Sophisticated
* Cinematic
* Spatial
* Precise
* Enterprise
* Calm
* Trustworthy
* Editorial
* Technological
* Human

---

## 1.3 Explicitly Avoid

Never introduce:

* Cyberpunk aesthetics
* Neon blue or purple glow
* Holographic HUD interfaces
* Gaming-inspired visuals
* Tron-style grids
* Cryptocurrency/Web3 aesthetics
* Sci-fi control panels

Every visual element must support clarity, trust, spatial storytelling, or product understanding.

# 3. Visual Philosophy

## 3.1 Primary Visual Principle

The entire website revolves around ONE coherent visual system:

# THE UNIFIED HOSPITAL DATA SYSTEM

This is the visual identity of the website.

It represents how every hospital department communicates through a shared information architecture.

The visual system conceptually contains:

* Registration
* Outpatient
* Inpatient
* Pharmacy
* Laboratory
* Radiology
* Electronic Medical Records
* Billing
* Asset & Logistics

These are not separate decorative objects.

They are components of one larger technological system.

The viewer should gradually understand this system as they scroll through the website.

---

## 3.2 Visual Hierarchy

Priority order:

1. 3D system / spatial composition
2. Editorial typography
3. Product content
4. Navigation
5. UI controls
6. Decorative details

Never reverse this hierarchy.

Cards, buttons, particles, icons, gradients, or decorative effects must never become more visually dominant than the primary 3D system.

---

## 3.3 Darkroom Presentation

The primary environment should feel like a sophisticated technological artifact displayed in a dark architectural gallery.

Use:

* large negative space
* dark surfaces
* subtle atmospheric depth
* restrained lighting
* precise typography
* cinematic framing
* controlled reflections
* realistic materials

The environment should feel expensive because of restraint and composition, not because of excessive effects.

## 4.2 Accent Rule

Healthcare Blue must remain restrained.

Use it primarily for:

* primary CTA
* active system state
* important data flow
* subtle system illumination
* selected navigation state

Do NOT use blue as:

* a background gradient
* a decorative glow everywhere
* icon fills across the interface
* borders around every object
* a neon lighting system

Blue should communicate activity and trust, not "futuristic technology."

---

## 4.3 No Secondary Accent

Do not introduce:

* green
* red
* orange
* purple
* cyan
* yellow

as additional design accents.

The visual identity depends on a controlled monochrome + healthcare blue system.

* Söhne Breit

* Space Grotesk

* 500

---

## 5.2 Body Typeface

Preferred:

* Inter

Body:

* 400

Emphasis:

* 500

---

## 5.3 Type Scale

| Role          | Size | Line Height | Weight |
| ------------- | ---- | ----------- | ------ |
| Caption       | 12px | 1           | 500    |
| Body Small    | 14px | 1.4         | 400    |
| Body          | 16px | 1.5         | 400    |
| Body Large    | 18px | 1.4         | 400    |

Use:

* scale
* whitespace
* placement
* contrast

instead.

---

## 5.4 Editorial Typography Rules

Section labels may use uppercase typography.

Example:

`01 — THE PROBLEM`

Major headlines should remain readable and intentional.

Avoid:

* excessive uppercase body copy
* excessive letter spacing
* tiny unreadable labels
* giant text without semantic purpose

Body copy should remain mixed-case and human-readable.

# 6. Spatial & Layout System

## 6.1 Layout Philosophy

The website should feel spatial rather than grid-heavy.

Prefer:

* full-viewport compositions
* asymmetrical layouts
* large negative space
* strong visual hierarchy
* editorial positioning
* cinematic object framing

Avoid making every section look like a dashboard.

---

## 6.2 Base Spacing

Base unit:

`4px`

Preferred scale:

`4, 8, 12, 16, 20, 24, 32, 40, 56, 72, 112, 128, 160, 204px`

Major sections may use significantly larger spacing when cinematic composition requires it.

---

## 6.3 Container

Maximum content width:

`1200px`

However, 3D scenes may use the full viewport width.

The 3D visual system is allowed to extend beyond the normal content container.

---

## 6.4 Section Height

Major cinematic sections should preferably use:

`min-height: 100vh`

Some sections may use:

`100vh–180vh`

when a pinned scroll sequence is required.

Do not force every section to exactly 100vh.

Use height according to storytelling needs.

---

## 6.5 Negative Space

Negative space is an intentional design element.

Do not fill empty space simply because it is available.

Empty space should create:

* scale
* importance
* calm
* anticipation
* visual hierarchy

# 9. 3D Visual System

The 3D system is the visual identity of the website.

## 9.1 Core Concept

Create one coherent 3D visual system representing:

# UNIFIED HOSPITAL DATA SYSTEM

It should feel like a physical technological artifact displayed inside a dark architectural environment.

It must NOT look like:

* a futuristic city
* cyberpunk infrastructure
* a gaming environment
* cryptocurrency visualization
* generic AI network
* glowing particle cloud
* sci-fi dashboard

---

## 9.2 System Architecture

The conceptual architecture is:

```text
                     REGISTRATION
                           |
                           |
LABORATORY -------- DATA CORE -------- PHARMACY
                           |
                           |
                    MEDICAL RECORD
                           |
                        BILLING
                           |
                    OPERATIONS
```

This should NOT literally appear as a diagram.

Translate the architecture into a sophisticated 3D composition.

The viewer should intuitively understand:

Many hospital units → one shared information system.

---

## 9.3 Central Data Core

The system should contain a central architectural element representing the shared database.

The data core may be represented through:

* a central geometric structure
* layered transparent surfaces
* precise circular or architectural geometry
* controlled illumination
* subtle internal movement

It should feel engineered rather than magical.

---

## 9.4 Module Objects

Each module should have a recognizable spatial relationship with the central system.

Possible representations:

* Registration
* Outpatient
* Inpatient
* Pharmacy
* Laboratory
* Radiology
* Medical Records
* Billing
* Asset & Logistics

Every object must have a semantic reason for existing.

Never add random objects merely to make the scene look complex.

---

## 9.5 Materials

Preferred materials:

* dark graphite
* matte polymer
* brushed metal
* smoked glass
* translucent technical surfaces
* subtle reflective surfaces

Use realistic material response.

Avoid:

* excessive chrome
* excessive glass
* unrealistic glowing materials
* rainbow reflections

---

## 9.6 Lighting

Lighting should feel cinematic and physical.

Use:

* soft ambient lighting
* subtle directional lighting
* controlled rim lighting
* restrained blue illumination
* soft atmospheric depth

Avoid:

* neon lighting
* strong colored fog
* excessive bloom
* giant light beams
* lens flare
* glowing everything

Blue should primarily illuminate active data pathways.

---

# 10. Spatial Storytelling

The 3D system should evolve through the entire website.

It is ONE system.

Do not create completely unrelated 3D scenes for every section.

---

## 10.1 Hero — Unified

The system begins fully connected.

The camera slowly observes the entire architecture.

The user sees:

* central data core
* connected hospital modules
* subtle data movement
* large negative space

Headline appears as editorial typography around the system.

---

## 10.2 Problem — Fragmentation

As the user scrolls:

The system begins separating.

Connections become distant.

Modules drift apart.

Data flow becomes interrupted.

The visual metaphor communicates:

Disconnected systems create disconnected data.

Do not use warning icons or dramatic red alerts.

The visual change itself communicates the problem.

---

## 10.3 Solution — Reconnection

The system gradually reconnects.

Modules move back toward the central data layer.

Connections become continuous.

The central data architecture becomes visually stronger.

Message:

> One database. Every unit connected.

---

## 10.4 Modules — Exploration

Individual modules become identifiable.

The camera moves closer.

Each module can temporarily become the visual focus.

Examples:

* Registration
* Pharmacy
* Laboratory
* Medical Records
* Billing

The system remains visible in the background.

This prevents the page from becoming a collection of unrelated cards.

---

## 10.5 Process — Implementation

The same system transitions through implementation stages:

`01 Assessment`

`02 Migrasi Data`

`03 Pelatihan Tim`

`04 Go-Live & Pendampingan`

The visual system can progressively become more complete and operational.

---

## 10.6 Trust — Stability

The system reaches a stable state.

Movement becomes calmer.

The visual communicates:

* reliability
* continuity
* operational maturity

Avoid adding meaningless animated statistics.

---

## 10.7 Final CTA — Complete System

The full system returns to its unified composition.

The camera slowly pulls back.

Large negative space surrounds the system.

Closing headline:

> Siap menyatukan sistem rumah sakit Anda?

CTA:

`Jadwalkan Demo`

The final scene should feel like the conclusion of a product film.

# 11. Motion System

Motion is part of the storytelling system.

Animation must never exist simply because animation is possible.

Every major animation must communicate:

* connection
* separation
* hierarchy
* transformation
* progression
* continuity

---

## 11.1 GSAP + ScrollTrigger

GSAP and ScrollTrigger are responsible for:

* cinematic scroll sequences
* 3D camera movement
* object separation
* object reconnection
* system transformation
* scale transitions
* depth transitions
* pinned storytelling
* section transitions

These should form the primary cinematic motion system.

---

## 11.2 Framer Motion

Framer Motion is responsible for:

* button interactions
* navigation transitions
* hover states
* component-level entrance animations
* small UI feedback
* micro-interactions
* modal/dialog transitions

Do NOT replace major GSAP / ScrollTrigger sequences with Framer Motion.

Both libraries must coexist.

---

## 11.3 Motion Character

Motion should feel:

* slow
* deliberate
* smooth
* spatial
* physical
* cinematic
* controlled

Avoid:

* aggressive bouncing
* excessive spring animation
* rapid scaling
* constant floating
* random rotation
* excessive parallax
* attention-seeking transitions

---

## 11.4 Scroll Philosophy

Scrolling should feel like moving a camera through the same physical environment.

The user should feel:

> "I am exploring one technological system."

Not:

> "I am scrolling through six unrelated animations."

The environment remains coherent.

The camera moves.

The system evolves.

The content changes.

# 21. Technical Implementation Rules

## 21.1 Framework

The project uses:

* Next.js
* React
* TypeScript
* Tailwind CSS

Follow the existing project architecture.

Do not introduce unnecessary frameworks.

---

## 21.2 3D

Use:

* Three.js
* React Three Fiber when appropriate
* @react-three/drei when useful

The 3D system should be reusable across sections.

Do NOT create a separate unrelated Three.js scene for every section.

Prefer one persistent 3D experience whose state changes according to scroll position.

---

## 21.3 Animation Stack

Use:

* GSAP
* ScrollTrigger
* Framer Motion

Responsibility:

GSAP / ScrollTrigger:

`cinematic storytelling`

Framer Motion:

`micro-interaction`

Three.js / React Three Fiber:

`spatial visualization`

Do not use multiple animation libraries for the same animation.

---

## 21.4 Performance

The 3D experience must remain performant.

Consider:

* lazy loading
* reduced geometry complexity
* instancing where appropriate
* optimized materials
* controlled pixel ratio
* avoiding unnecessary post-processing
* responsive quality settings
* reduced motion support

The website must remain usable on normal laptops.

Do not sacrifice usability for visual effects.

---

## 21.5 Responsive Behavior

Desktop is the primary cinematic composition.

Tablet and mobile should preserve the visual concept without forcing the exact desktop composition.

On mobile:

* simplify the 3D scene
* reduce object count
* reduce animation complexity
* prioritize readable typography
* maintain the central system concept

Never allow 3D to block or obscure important content.

---

# 22. Accessibility

Maintain:

* readable contrast
* semantic HTML
* keyboard navigation
* visible focus states
* accessible buttons
* meaningful link labels
* reduced-motion support

When `prefers-reduced-motion` is enabled:

* reduce camera movement
* disable unnecessary object transitions
* minimize parallax
* preserve content and hierarchy

The website must remain understandable without animation.

---

# 24. Design Decision Hierarchy

When requirements conflict, follow this hierarchy:

1. Product clarity
2. Brand credibility
3. Spatial storytelling
4. Typography
5. Composition
6. Motion
7. Decorative effects

Never sacrifice product clarity for visual effects.

Never sacrifice performance for unnecessary 3D complexity.

Never sacrifice readability for cinematic composition.
